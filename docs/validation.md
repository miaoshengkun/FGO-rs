## 第三阶段：连续出击与实机验证（2026-09-10）

新增 `farming.rs`、`farm_vision.rs` 和 `scripts/rider_farm.rhai`，接入选关、助战刷新、编队确认、AP 额度、结果页和连续出击。CLI 新增 `--battles`、`--apples`、`--apple-kind`、`--frames` 与 `inspect --farm`。独立助战脚本也接入同一刷新流程。

实机为本地 MuMu，ADB 地址 `127.0.0.1:5559`，原始截图 1920×1080。使用 Rust 发布程序截图和发送输入，实际完成 3 场骑阶冠位战，均为 1 回合：

- 第一场验证技能、我方目标、1/5 换人、御主技能和首轮三宝具；胜利后停在牵绊结果页，发现旧识别只等待战利品页。补齐牵绊和经验结果模板后完成结算。
- 随后 `rider_farm.rhai --battles 0 --apples 0` 连续完成 2 场，自动选好友、战斗、推进牵绊/经验/战利品结果并再次出击；AP 不足时关闭恢复窗口，日志确认 `Farming stopped: 2 battles, 0 apples remaining`。
- 另外运行 `--apples 1 --apple-kind bronze`，实机确认最低需要 2 个赤铜果实，程序取消确认并退出，日志保留 1 个额度。本次没有消费苹果或圣晶石；游戏原有的其他道具自动使用设置保留。

实机发现并修复：敌人详情弹窗不能当成技能目标弹窗；胜利先出现牵绊、经验结果；AP 不足时选关可能直接打开恢复窗口；赤铜果实使用当前游戏的批次数量界面，需要按实际个数核对额度。

本地证据保存在被 Git 忽略的 `logs/`：`live-battle1b.jsonl` 为首场战斗，`settle2.jsonl` 为补齐后的结算，`live-farm.jsonl` 为完整连续 2 场，`live-ap-budget.jsonl` 为最低批次超过额度的取消流程。相应 `*-frames/` 保存全部观察画面，精选截图纳入 `tests/fixtures/live-*.png` 回归。

最终本地检查：60 项测试通过，另有 2 个由父测试调用的子进程夹具标为 ignored；`cargo fmt --all -- --check`、`cargo clippy --locked --all-targets -- -D warnings` 和 Windows GNU 发布构建通过。新增测试覆盖真实结算宿主调用、页面互斥、AP 直接打开、苹果种类与 1～4 个批次识别、批次预算、模糊恢复结果不重试、助战刷新间隔及上限。

验证边界：未实际消费苹果验证恢复后续战；蓝色青铜果实库存为 0，缺少确认页样本，未开放对应 CLI 选项。助战刷新确认页已实机采集，但本次连续战斗均在第一次列表找到好友，完整的多次刷新由模拟状态测试覆盖。后续多回合、败北和特殊掉落分支尚未实战触发。仍未迁移最高 HP 选敌、通用战斗、OCR 和 GUI。macOS 构建及实际运行仍待验证，CI 配置未在远程执行。
